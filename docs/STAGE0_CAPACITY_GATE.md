# Stage 0 Capacity and Competency Gate

## Decision

The previous `causal_basics` session is **rejected as a language-learning pass**. It proved that the optimizer, checkpoint, validation, and deterministic artifact pipeline function, but the trained checkpoint generated the same byte token eight times for every fixed prompt. That is a degenerate output policy, not acceptable Stage 0 English learning.

## Minimum diagnostic capacity

The next Stage 0 checkpoint must use the following configuration rather than the two-dimensional smoke-test model:

| Field | Required value | Reason |
|---|---:|---|
| Vocabulary | `260` | Exact `attention.byte_utf8.v1` tokenizer contract |
| Context length | `32` | Gives the model enough local context for short English continuations |
| Transformer layers | `2` | Minimum depth for a nontrivial composition test |
| Hidden size | `32` | Minimum useful representation width for the diagnostic model |
| Attention heads | `4` | Head size `8`; maintains a valid multi-head configuration |
| Feed-forward size | `128` | Four-times expansion for the block MLP |
| Precision | `F32` | Current implemented numerical path |
| Dropout | `0` | Deterministic diagnostic training |

This configuration has approximately **34,628 trainable scalar parameters** under the current parameter-count contract. It remains a bounded CPU diagnostic model, not a claim about the final production model.

## Training budget

The next run must use a real bounded English chunk, not 32 total tokens. The minimum diagnostic target is **at least 4,096 training tokens and 1,024 disjoint validation tokens**, with repeated deterministic passes over the selected chunk until the learning curve is measurable. The run must use an analytical or otherwise scalable backward path; central finite differences are retained only for small correctness tests and must not be the production training path for this capacity.

## Automated pass gates

A Stage 0 session may not be promoted unless all of the following pass:

1. Training loss decreases by at least 20% from the initial measured loss on the bounded training chunk.
2. Validation loss is finite and improves relative to the untrained parent, or the report explicitly records a controlled overfit experiment with a separate held-out result.
3. Gradient norms are finite, nonzero, and do not diverge.
4. The checkpoint and training-state reload reproduce the recorded loss within exact serialized determinism.
5. At least three of four fixed continuation prompts produce a non-repeating continuation with at least two distinct generated byte tokens.
6. The generated continuation is valid UTF-8 after decoding, or the report records the exact invalid-byte failure.
7. Repeated greedy evaluation is byte-for-byte deterministic.
8. The live-source complexity scan remains free of dense token-pair allocation or O(n²) token-pair computation.

## Fixed prompts

The first evaluation set is:

```text
The sky is
Once upon a time
A cat sat on the
The capital of France is
```

The first gate does not require factual correctness for every prompt. It requires that the model stop collapsing to one repeated byte and demonstrate a measurable, deterministic local continuation signal. Meaningful English quality is evaluated in the next competency after this gate.

## Latest upgraded-capacity trial

The upgraded two-layer, hidden-32 configuration with analytical reverse-mode gradients was trained for 2,048 steps on a bounded 512-token English chunk at learning rate `0.005`. Training loss decreased from `5.51386404` to `3.31816936`, a `39.82%` reduction, and held-out validation loss reached `4.24915648`. Checkpoint reload and training-state reload reproduced the final loss exactly.

The language-generation gate still failed: all four fixed prompts greedily generated byte token `32` repeatedly. The pipeline and optimization gates therefore pass, but **Stage 0 English competency remains failed and the checkpoint must not be promoted**. The next trial must use the real FineWeb English chunk with the upgraded configuration and the `4,096/1,024` train/validation budget. If that also collapses, the failure analysis must inspect token distribution, target construction, optimizer scale, and output decoding before considering architectural changes.

## Failure interpretation

A failure at this gate is not automatically an architectural failure. The report must separate data quality, tokenizer coverage, target construction, optimizer scale, backward correctness, and model capacity. If the upgraded configuration, scalable backward path, independent English chunks, and stable optimizer settings all fail the same gate, the project should stop and investigate the architecture rather than silently advancing the curriculum.
